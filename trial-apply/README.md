# 체험단 신청 자동화

무선 디버깅으로 붙은 안드로이드 폰에서 메신저 앱 선물하기의 체험단 탭을 훑고, 신청 기준에 맞는 상품을 자동으로 신청하는 스크립트 모음이다. uiautomator2 로 화면에 뜬 앱의 노드(text / content-desc / bounds)를 직접 읽고 누른다.

체험단 목록은 불러올 때마다 큰 풀(400개 이상)에서 98개쯤을 무작위로 보여 준다. 그래서 목록을 여러 번 다시 불러오며 상품명 기준으로 결과를 쌓고, 이미 결과가 확정된 상품은 다시 열지 않는다.

## 주요 기능

- mDNS 로 무선 디버깅 기기를 찾아 adb 로 연결 (`scripts/connect.sh`)
- 체험단 탭 진입, 목록 스크롤, 카드 읽기, 세션 만료 팝업 처리 (`trial.py`)
- 상품명 키워드로 신청 여부 판정 (`classify.py`)
- 상세 > 위시 담기 > 옵션 선택 > 신청 완료까지 자동 진행, 상품별 결과 저장과 이어 하기 (`scripts/apply.py`)
- 화면 노드 덤프, 단계별 흐름 추적 같은 디버그 도구

## 요구 사항

- Python 3.12 이상, [uv](https://docs.astral.sh/uv/) (의존성: `uiautomator2>=3.7.1`)
- adb (Android SDK platform-tools, PATH 에 있어야 함)
- 무선 디버깅을 켠 안드로이드 폰, PC 와 같은 Wi-Fi
- 좌표 상수는 1440 x 3120 해상도 기기 기준이다 (다른 해상도에서는 맞지 않을 수 있다)

## 설정

대상 앱 패키지명은 코드에 적지 않고 프로젝트 루트 `.env` (git 제외) 에 둔다. 환경변수로 줘도 된다.

| 변수 | 내용 |
| --- | --- |
| `TRIAL_APP_PACKAGE` | 대상 메신저 앱 패키지명 (필수) |
| `ANDROID_SERIAL` | 붙을 기기 주소. 보통 `scripts/connect.sh` 출력으로 넘긴다 |

## 설치와 실행

```bash
uv sync                                    # .venv 생성, 의존성 설치

scripts/connect.sh pair <ip:port> <code>   # 최초 1회 또는 페어링이 풀렸을 때
export ANDROID_SERIAL="$(scripts/connect.sh)"

uv run python -u scripts/apply.py --passes 25 > local/run.log 2>&1
```

### connect.sh

```bash
scripts/connect.sh                        # 탐색 + 연결, 붙은 주소를 stdout 에 출력
scripts/connect.sh pair <ip:port> <code>  # 페어링
scripts/connect.sh off                    # 연결 해제 + 주소 캐시 삭제
```

1. 이미 무선으로 붙은 기기가 있으면 그대로 쓴다
2. 없으면 직전에 성공한 주소(`~/.cache/trial-apply/endpoint`)로 다시 붙어 본다
3. 그래도 안 되면 mDNS(`_adb-tls-connect._tcp`)로 찾아 `adb connect` 한다 (macOS 는 `dns-sd`, 그 밖에는 `adb mdns services`)

- 무선 디버깅을 껐다 켜면 포트가 바뀐다. `adb connect` 가 바로 `failed to connect` 를 내면 페어링이 풀린 것이다.
- 페어링 포트는 무선 디버깅 첫 화면의 포트가 아니라 "페어링 코드로 기기 페어링" 창에 뜨는 포트다.

## 사용법

### scripts/apply.py (자동 신청)

목록을 다시 불러오며 위에서부터 훑고 판정대로 신청한다. 새 상품이 거의 안 나오는 패스가 3번 이어지면 끝난다.

| 옵션 | 내용 |
| --- | --- |
| `--passes N` | 목록 다시 불러오기 횟수 (기본 30) |
| `--limit N` | 최대 처리 상품 수 |
| `--only 상품명일부` | 이름에 이 문자열이 들어간 상품만 처리하고 한 패스로 끝낸다 |
| `--deep` | 패스마다 더보기를 끝까지 눌러 풀 전체(약 480개)를 훑는다. 한 패스 10분쯤 |

- 실행 중에는 폰을 쓰지 않는다. 화면이 꺼지거나 다른 앱이 앞에 오면 멈추거나 앱을 다시 띄운다.
- 끊으려면 프로세스를 죽이면 된다. 결과가 상품마다 저장되니 다시 돌리면 이어서 한다.
- 새 체험단이 올라온 뒤 한 번 더 훑을 때는 `--deep --passes 2` 정도면 된다.

결과 상태: `신청 완료` / `이미 신청됨` / `맞는 사이즈 없음` / `제외` / `질문` / `신청 불가` 는 확정으로 보고 다시 열지 않는다. `확인 필요` 는 다음 실행 때 다시 시도한다.

### 그 밖의 스크립트

모두 `uv run python scripts/<이름>.py ...` 로 실행하고 `ANDROID_SERIAL` 을 쓴다.

| 명령 | 하는 일 |
| --- | --- |
| `collect.py [--more N]` | 목록을 끝까지 스크롤하며 상품명을 `local/items.json` 에 모은다. `--more` 는 더보기 누를 횟수 |
| `screen.py [out.xml]` | 현재 화면 노드를 bounds / 클래스와 함께 출력한다. 인자를 주면 XML 덤프도 저장 |
| `tap.py <라벨>` | text 또는 content-desc 가 라벨인 노드를 누른다 |
| `probe.py <상품명일부\|SIZE>` | 상품 하나를 열어 위시 시트, 옵션 드롭다운까지 가서 화면을 출력한다. 신청하지 않는다. `SIZE` 는 결과가 맞는 사이즈 없음인 상품 |
| `trace.py <상품명일부\|AUTO> [--go]` | 신청 흐름을 단계별로 화면을 찍으며 따라간다. `--go` 일 때만 신청 완료까지 누른다. `AUTO` 는 아직 처리 안 된 apply 대상 |

## 신청 기준

판정은 `classify.py` 가 상품명 키워드로 한다. 상품명에 "출산 선물", "100일" 같은 홍보 태그가 많이 붙어 있어서 키워드는 상품 자체를 가리키는 말만 쓴다.

| 판정 | 대상 |
| --- | --- |
| skip | 아기/육아용품 (신생아, 젖병, 터미타임, 조리원, 동물인형 등), 김치 |
| size | 의류/신발 (잠옷, 티셔츠, 팬츠, 조끼, 신발, 슬리퍼 등), 프리사이즈 소품 (장갑, 볼캡, 양말) |
| apply | 그 밖의 전부 (화장품, 주얼리, 향수, 먹거리, 스킨/바디케어 등) |
| ask | 새로 애매한 종류가 나오면 `RULES` 에 추가해서 사용자에게 묻는 용도 |

- 사이즈: 신발 270 이상, 옷 XL / 2XL / XXL / 105 / 110 을 고른다. 맞는 옵션이 없으면 가장 큰 옵션(남성용 > L > FREE > M > S)을 고른다. 품절 옵션은 건너뛴다.
- 일반 상품의 옵션은 첫 번째 것을 고르고 결과에 남긴다. 옵션 드롭다운이 이어서 나오면(색상 > 사이즈) 최대 3단계까지 고른다.
- 위시리스트 공개 범위, 배송지, 배송 요청사항은 기본값 그대로 둔다.
- 특정 상품만 다르게 하려면 `local/overrides.json` 에 `{"상품명": {"mode": "skip"}}` 처럼 적는다. 판정보다 우선한다.

## 화면 흐름

앱 안의 웹뷰지만 uiautomator 로 텍스트와 bounds 가 잡힌다.

1. **진입**: 메신저 앱 친구 탭 상단 `선물하기` > 상단 탭 줄(가로 스크롤) 오른쪽 끝 `체험단`.
2. **목록**: 2열 카드 그리드(x 64 또는 736, 폭 640), 카드 content-desc 가 상품명 전체다. 맨 위에서는 탭 줄이 y 289 ~ 469 에 있어서 카드를 누를 때 y 520 위쪽은 피한다. 웹뷰가 스와이프를 탭으로 받아 상세가 열리면 뒤로 간다.
3. **상세**: 하단 버튼으로 상태를 판별한다. `선물 체험단 신청하기`(x 232 시작) 는 신청 가능, `이미 신청한 체험단입니다` 는 이미 신청함.
4. **위시 담기 시트** (위시에 없는 상품만): `위시에 담고 신청하기` 를 누르면 옵션 시트로 넘어간다.
5. **옵션 시트**: `옵션을 선택해주세요` 드롭다운을 열면 옵션이 위쪽에 `[68,y][1372,y]` 노드로 쌓인다. 고르면 하단 버튼이 `선물 체험단 신청하기`(x 64 시작) 로 바뀐다. 상세 버튼과 텍스트가 같아서 bounds 로 구분한다.
6. **신청 페이지**: `신청 완료하기` 를 누른다. 위시 토스트가 하단을 덮어 첫 탭이 먹지 않을 때가 있어서 다시 누른다.
7. **완료 팝업**: `체험단 신청이 완료되었습니다.` > `닫기` 후 뒤로 가서 목록으로 돌아온다.

오래 쓰면 `사용자 인증에 실패하였습니다` 팝업이 뜬다. `닫기` 로 선물하기를 닫고 다시 들어간다 (`open_trial_tab` 이 처리한다).

## 디렉터리 구조

```
.
├── trial.py           # 공용 함수: 연결, 화면 판별, 체험단 탭 진입, 스크롤, 카드 읽기
├── classify.py        # 상품명 키워드 판정 (skip / ask / size / apply)
├── pyproject.toml     # uv 프로젝트 설정
├── .env               # TRIAL_APP_PACKAGE (git 제외)
├── scripts/
│   ├── connect.sh     # 무선 디버깅 기기 탐색/연결/페어링
│   ├── apply.py       # 자동 신청
│   ├── collect.py     # 목록 수집
│   ├── screen.py      # 화면 노드 출력
│   ├── tap.py         # 라벨로 노드 누르기
│   ├── probe.py       # 옵션 시트까지 확인 (신청 안 함)
│   └── trace.py       # 신청 흐름 단계별 추적
└── local/             # 개인 기록 (git 제외)
    ├── results.json   # 상품명별 결과 (이어 하기용)
    ├── overrides.json # 상품별 판정 덮어쓰기 (선택)
    └── items.json     # collect.py 결과
```

`local/` 아래 진행 기록, 신청 결과, 캡처, 로그는 개인 기록이라 `.gitignore` 로 제외한다.
